# 互联网医院牌照与实体依托关系分析（决策备忘）

> 形成日期：2026-07-04。背景：天津逑贝互联网医院依托实体机构**天津滨海空港逑贝诊所**开展互联网诊疗，
> 诊所每年维护成本较高，管理层提出"能否只保留互联网医院、注销线下诊所"。本文是对该问题的
> 政策分析与决策建议，供内部决策与后续和卫健委沟通时使用。
>
> ⚠️ 本文为内部研判，非法律意见。涉及牌照存续的最终动作，务必先与登记机关（天津市/滨海新区卫健委）书面确认。

---

## 一、结论

**不能。互联网医院必须依托实体医疗机构，没有"纯线上"选项。**
滨海空港诊所若注销，天津逑贝互联网医院的执业资质随之失效——诊所是互联网医院牌照的"锚"。

## 二、政策依据

1. **《互联网医院管理办法（试行）》**（国卫医发〔2018〕25 号）：互联网医院只有两种形态——
   ① 作为实体医疗机构第二名称的互联网医院；② 依托实体医疗机构独立设置的互联网医院。
   两者都必须以实体医疗机构为依托，**不允许设立纯虚拟的互联网医院**。
2. **《互联网诊疗监管细则（试行）》**（国卫办医发〔2022〕2 号）：进一步强化实体依托的实质作用——
   线上诊疗出现病情变化须能转至线下实体处置、病历等资料依托实体保管、监管责任落到实体属地。
   近年监管方向是**趋严**（打击"空壳互联网医院"），不存在放开纯线上的政策窗口。
3. **实体注销的后果**：依托的实体医疗机构注销后，互联网医院应当同时注销（病历移交省级卫生健康
   主管部门指定机构保管）。

## 三、我院的登记形态与含义

从监管平台机构档案（2026-07-03 截图）判断：

| 项 | 值 | 含义 |
| :-- | :-- | :-- |
| 机构名称 | 天津逑贝互联网医院（独立名称） | 属**独立设置型**互联网医院 |
| 申请方式 | 医疗机构与第三方合作申请 | 实体（诊所）+ 第三方（技术方）合作模式 |
| 依托实体 | 天津滨海空港逑贝诊所 | 牌照存续的前提 |

**独立设置型的关键约束**：按管理办法，**合作方发生变更或合作协议失效的，应当注销互联网医院；
变更后仍需设立的，须重新申请设置**。也就是说：

> "换一家实体来依托" ≠ 变更登记，而是 **"注销 + 重新设置审批"**——
> 2023 年取得的牌照作废重办，周期以月计，期间业务断档；监管平台档案（unitID
> `20250813151647906`、组织机构代码、测试达标状态、密钥）全部重新对接。

## 四、可选路径对比

| 路径 | 可行性 | 成本/风险 | 建议 |
| :-- | :-- | :-- | :-- |
| A. 注销诊所、只留互联网医院 | ❌ 政策不允许 | 牌照直接失效 | 排除 |
| B. **保留诊所，压到最低合规配置** | ✅ | 按《诊所基本标准》维持：场地 + ≥1 名注册执业医师 + 基本设备，按期校验 | **推荐**：把诊所维护费视为互联网医院的"牌照成本"核算 |
| C. 换依托实体（与第三方实体合作） | ⚠️ 法规允许但代价大 | 注销重办、数月断档、监管对接重做、需稳定合作方 | 仅当找到长期稳定合作医院且 B 成本确实不可承受时立项评估；**必须新牌照落地后再注销诊所** |

## 五、决策建议

1. **短期（本年度）不动诊所**，专注互联网医院业务上量；同步把诊所配置压至《诊所基本标准》下限。
2. **算总账**：诊所年维护成本 vs 互联网医院业务收入预期。互联网医院是主营方向的前提下，
   这笔锚定成本大概率值得保留。
3. 若未来评估路径 C，按"先立后破"执行：新依托关系的设置审批批下来之前，诊所一天都不能注销。
4. 与登记机关确认两件事（建议随 T5 沟通一并办理或单独致函）：
   - 我院登记形态的官方认定（独立设置 vs 第二名称）；
   - 若未来变更依托实体，具体流程、材料与周期。

## 六、附带：远程会诊业务的定位

远程会诊是**医疗机构之间**的医疗行为（申请方机构 ↔ 受邀方机构）。对我院的现实影响目前仅限
监管接口范围问题（监管平台将其标记为"需要对接"，疑为当年第三方申报误勾，处理见
[S0 手册](tianjin_supervision_s0_checklist.md) T5 第 13 问）。

反向思考：**"诊所 + 互联网医院"的组合恰好是开展远程会诊的合法结构**——诊所作为基层申请方，
将疑难患者远程提交上级医院专家会诊。若未来把它作为真实业务开展，既能提升诊所的存在价值
（回应"每年花钱维护"的问题），监管上报侧我方网关架构已就绪，补一个 mapper 即可支持。
